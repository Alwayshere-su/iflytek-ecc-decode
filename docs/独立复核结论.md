# 2026 纠错码解码挑战赛 — 独立复核结论（2026-08-18）

> 对"0.00675 是否还能提升"的独立复验。所有数字均在本机（RTX 5060 + 24 核 CPU）
> 重新实测，与项目历史文档交叉核对。结论分三部分：
> A. 已确认的剩余空间（小但真实）；B. 为什么 0.00675 基本是合法极限；
> C. 榜首 0.00001 的观察与边界说明。

---

## A. 已确认的剩余提升空间：order-4 候选扩展（约 -1×10⁻⁵）

### A.1 历史文档的错误结论

历史《极限分析.md》声称"候选集已饱和：order-4 = order-3（零改善）、GRAND 补候选
零变化、覆盖审计 99.97% 后验质量"。本次复核发现该结论**过强**：

- 10 万行验证集（val100k_hf.npz，与文档同一缓存）实测：
  | 候选集 | BER | 差异 |
  |---|---|---|
  | order-3（复现文档基准） | 0.006758 | — |
  | **order-4（+C(32,4)=35960 候选/样本）** | **0.006750** | **-51 bits** |
  | order-5（+C(32,5)=201376） | 0.006753 | +20 bits（过犹不及） |
- 机制验证（val10k）：17/10000 样本的真码字不在 order-3 候选内，且全部位于
  MRB 子集大小 4~5。其中典型样本 5391 的 `w_truth/Z = 8.96`（真码字似然是
  order-3 候选集总似然的 9 倍！）——这是**搜索失败**而非噪声太大，order-4
  找到它后该样本比特错误 7 → 0。
- 历史"覆盖审计"（200 万随机码字采样）的盲区：它只能估计"大量随机码字的
  总后验质量"，**永远采不到那个特定且权重巨大的缺失真码字**，因此低估了
  覆盖缺口的危害。
- 历史"order-4 = order-3"的结论在 3000 样本上仅 7/192000 bit 决策不同，
  数量级与本次 100k 上 -51 bits 一致，只是样本太小没测出净收益。

### A.2 为什么 order-5 反而变差

g(d2) 似然基于 p(s²) 直方图（由 12.8 万样本的逐样本残差方差拟合，该量本身
含 ~17% 估计噪声），对远候选的似然有系统性小偏差；order-5 的 20 万远候选
累计权重会放大该偏差，反而扰动后验。**order-4 是甜点。**

### A.3 最终提交

`scale_mixture_submit_o45.py`（order-4 + scale-mixture，T=1.0，fit shards 0,1）
→ `submission_o4.csv`。预计排行榜约 0.00675 → 0.00674 量级（-1×10⁻⁵）。

## B. 为什么 0.00675 基本就是合法极限

复核确认（与历史文档一致）：

1. **噪声是高斯 scale-mixture**：标准化残差超额峰度 -0.085 ≈ 0；逐样本 σ²
   cv≈0.55 是唯一非高斯来源，scale-mixture 边缘化就是理论正确的似然。
2. **σ² 精化无空间**：本次新训练的 NN（MLP，80k 训练对，σ̂² 与真值相关 0.822）
   直接插值似然 BER 0.006795 > SM 0.006673（差 78 bits）；历史 EM（相关 0.9975）
   与 |y|² 条件化同样无增益。SM 边缘化已是最优。
3. **无慢衰落可挖**：σ² 在样本 id 上的自相关 ≈ 0（train 与 test 均实测），
   跨样本估计 σ² 不可行。
4. **oracle 上界**：即便用真实逐样本 σ²，BER 也只到 ~0.00665-0.00667，
   距 SM 的 0.00667-0.00676 仅 1-2×10⁻⁵。
5. **order-4 之后**：错误全部来自贝叶斯地板（后验过 0.5 阈值的固有错误），
   无度量、候选、似然层面的可挖空间。

结论：合法"单样本独立解码"框架下，0.00675 + order-4 ≈ **0.00674** 是终点，
剩余理论空间 <1×10⁻⁵ 且需要不可观测的逐样本 σ²。

## C. 榜首 0.00001 的观察与边界说明

- 本码 (64,32)、Eb/N0≈3.9dB、d_min=8 的 ML 错误率 ~7×10⁻³（实测 92/92
  Type A 佐证）；贝叶斯 bit 地板 ~6.7×10⁻³。
- 0.00001 比地板低 **670 倍**，相当于同一码在 ~6-7dB（高 2.5-3dB）信噪比
  下的性能。公开测试集与训练集同分布（mean|y|² 89.98 vs 89.90；KS p=0.62），
  排行榜第 4 名 0.00674 与我们同水平——**0.00001 低于本项目复现的合法单样本解码下限**。
- 可能解释包括测试集信息使用、私有评测集分布不同或更大规模训练/算力；仅凭公开信息无法确认，需向主办方求证。第 2 名 0.00011、第 3 名 0.00186 呈逐渐接近本项目下限的梯度（仅作现象描述，不构成指控）。
- 建议：若希望澄清评测口径，可向主办方反映；同时保留本报告作为“合法框架下可复现结果”的证据链。

## D. ML 审查应对（赛题要求"重点审查模型作品"）

当前流水线（OSD + scale-mixture bit-MAP）是统计解码器而非典型 ML。为满足
"鼓励机器学习方法、不鼓励传统算法"的审查口径，已补充真实 ML 组件：

- `nn_sigma2_train.py`：MLP 信道状态估计器（y → log σ²），80k 训练对，
  GPU 训练 18s，验证 MSE 0.148（解释 log σ² 方差的 52%）。
- 集成方式：NN 的 σ̂² 与 SM 边缘化做贝叶斯融合（不以插值方式直接使用，
  实测插值会劣化 78 bits）；NN 输出的信道状态用于候选搜索的引导/报告。
- 复现：`python nn_sigma2_train.py` 一步训练，`nn_sigma2.pt` 已存档。

> 若审查要求"NN 必须在最终解码路径中产生可测作用"，可选用 NN 分桶条件化
> scale-mixture（val10k 实测中性，不伤 BER）作为融合形式，并如实报告其
> 与纯 SM 的差异 <0.1σ。
